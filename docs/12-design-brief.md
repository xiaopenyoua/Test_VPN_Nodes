## 1. 一句话与判据

**ProxyLens 是本地运行的系统代理能力探测器。** 它不测某个 Clash 节点，它回答一个问题：**「我现在这套出网方式，能不能顺畅用 ChatGPT / Gemini，卡在哪一层？」**

设计的唯一判据不是"好看"，是这一条：

> **界面上的结论，必须和用户当场用浏览器打开 ChatGPT 看到的结果一致。**
> 只要界面说"可用"而浏览器打不开，这个界面再漂亮也是失败的。

所以下面所有视觉取舍都服务一件事：**让"结论"和"证据"一眼能对上**。

## 2. 功能盘点（按代码事实）

### 2.1 出口模式（三选一，地址可留空）

| 模式 | 语义 | 界面要求 |
|---|---|---|
| 系统代理 | 走 OS 默认出网（TUN 下即按系统路由出） | 地址可留空；跑起来显示识别到的真实路径 |
| 自定义代理 | `http/https/socks5/socks5h` + 可选 `user:pass` | 输入即切模式；折叠时掩码 `//***@`；不落盘 |
| 直连对照 | 强制忽略所有代理 | 用于和代理结果对比 |

### 2.2 六个探测项

| ID | 名称 | 真实请求 | 能给出的判断 |
|---|---|---|---|
| P3 | ChatGPT 网页 | `chatgpt.com` 首页 + 静态资源 | 可用/受限/被风控/地区受限/疑似劫持；附 `loc·colo·WARP` 出口身份 |
| P4 | Gemini 网页 | `gemini.google.com` 首页 | 可用 / 地区受限 |
| P5 | OpenAI API | `api.openai.com/v1/models` | 401 也算"网络与服务可达"（可达 · 需 Key） |
| P6 | 国际链路基线 | `google.com` / `gstatic.com` 多次采样 | RTT、抖动、成功率 |
| P2 | YouTube 链路 | 首屏 + 缩略图 + `googlevideo` 分片 | 可看 / 可开但无媒体流 / 被要求验证 |
| P1 | Google 大文件下载 | `dl.google.com` 流式下载（不落盘） | Mbps、TTFB、速度衰减、断流时刻、有效吞吐占比 |

**状态共 12 种**（待测/未执行/探测中/可用/可达·需 Key/受限/无法确认/限流·网络通/被风控/地区受限/疑似劫持/不可达/已取消）。必须"颜色 + 文字"同时出现，不能只靠色。

### 2.3 强度与长跑

| 档位 | 下载时长 | 流量预算 | 单请求超时 | 并发 |
|---|---|---|---|---|
| 快速 | 8s | 20 MB | 15s | 1 |
| 标准 | 15s | 64 MB | 20s | 1 |
| 深度 | 30s | 160 MB | 25s | 1 |

**长跑**：1800s / ≥1024 MB / 强制单流。输出三个短测给不出的数字——**首次掉零时刻 `StallAtMs`**、**有效吞吐占比 `SustainPct`**、**分窗采样序列**。这是用户原话「好多只能下几十秒就不行了」的正面回答。

### 2.4 评分

- 三维：**速度 40%（P1，取 P2 较优值）/ 稳定性 30%（P6 成功率 + 抖动）/ AI 可用性 30%（P3 40% + P4 35% + P5 25%）**。
- 未测维度不参与加权，按实际参与项重新归一 —— 所以"未测"显示 `—`，不能显示 0。
- 封顶必须露出：P3 被风控 → AI ≤ 60；P3+P4 均地区受限 → AI ≤ 25；任一证书异常 → 总分 ≤ 55。
- 三态裁定：`AI 可用` / `AI 受限` / `AI 不可用`。

### 2.5 单项复测（`only=true`）

只跑一项，**保留其它五项结果、不重算总评**。卡片自报「单项复测 · 不参与总评」，总评页提示"总评仍来自上一次完整探测"。

### 2.6 详情抽屉

阶段耗时瀑布（DNS / TCP / TLS / TTFB）· 吞吐曲线 · 原始证据 KV · 归因（本地/代理/目标站/未定）· **下一步该做什么**。

### 2.7 其它已实现

导出 Markdown / JSON · SSE 采样级实时流 · 出网方式识别（含 warnings）· 主题三态（auto/light/dark，首帧不闪）· 键盘（Enter 开跑 / Esc 关抽屉）· 桌面握手（`?shell=electron` → 红绿灯安全区 38px）。

## 3. 用户与任务

| 用户 | 场景 | 打开那一秒的问题 | 界面要立刻给 |
|---|---|---|---|
| 折腾型 | 换了新机场，白天好晚上卡 | 是不是节点的问题？ | 一句话裁定 + 哪项拖后腿 |
| 半技术型 | ChatGPT 打不开，不知是账号、地区还是网络 | 卡在哪一层？ | P3 状态 + 归因 + 换什么 |
| 排障者 | 帮别人看，要留证据 | 怎么讲清这次结果？ | 一键导出 + 可截图的结论块 |

共同点：**不读日志，只读结论**。必须先给结论、再给证据，两者同屏可对照。

## 4. 设计原则（五条，用来取舍）

1. **答案先于证据。** 首屏第一块是结论，不是配置。配置折叠成一行摘要，要改再展开。
2. **一个数字说话。** 总分是唯一巨型元素；其余数字降到等宽小字。
3. **颜色只给数据和状态。** 骨架全中性，彩色像素 < 5%；红=坏、黄=受限、绿=好，每处配文字。
4. **安静不等于空。** 用密度填空：真实指标、真实证据、真实下一步。
5. **桌面形态优先。** macOS 控件语言（圆角矩形按钮、8px 分段控件、51×31 开关、分组列表），不用 iOS 胶囊与大圆角。

```
窗口
├── 侧栏 232px     品牌 · 总评/分评/设置 ·（底部）主题三态
├── 工具栏 48px    页面名 + 一句话副题 ······ 唯一全局动作：导出报告
├── 内容纸
```

**关键顺序改动**：现状是「探测条件」占首屏最大块、结论在其下。改为**结论卡置顶**，条件降为结论卡下方的一行摘要。用户来是看结论的，不是来填表单的。

## 6. 视觉规范（macOS / HIG 映射）

### 6.1 字体

| 角色 | 字号 | 字重 | 说明 |
|---|---|---|---|
| 总分 | 64 | 600 | 显示字面，`tabular-nums`，`-0.03em` |
| 页面标题 | 22 | 600 | 全文档唯一 `h1` |
| 裁定句 | 17 | 500 | 一行说清"能用 / 不能用" |
| 正文 | 13 | 400 | macOS 默认正文 |
| 标签/次要 | 12 | 400 | `secondaryLabel` |
| 数字/指标 | 13 | 500 | `tabular-nums`，右对齐 |

字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", system-ui`。

**删掉自托管的 Inter**：装不装得上都是不确定因素，系统字体才是 Apple 的样子，也省一个 200KB 预载。

### 6.2 颜色（语义令牌，两套）

| 角色 | Light | Dark |
|---|---|---|
| 窗口底框 `chrome` | `#f5f5f7` | `#1c1c1e` |
| 内容纸 `sheet` | `#ffffff` | `#131315` |
| 卡片/行 `surface` | `#ffffff` | `#1c1c1e` |
| 抬升 `raised` | `#f5f5f7` | `#2c2c2e` |
| 分隔 `separator` | `#e5e5ea` | `#38383a` |
| 主文字 `label` | `#1d1d1f` | `#f5f5f7` |
| 次文字 `secondary` | `#6e6e73` | `#a1a1a6` |
| 弱文字 `tertiary` | `#86868b` | `#8e8e93` |
| 强调 `accent` | `#007aff` | `#0a84ff` |
| 好 `green` | `#248a3d` | `#30d158` |
| 受限 `orange` | `#b25000` | `#ff9f0a` |
| 坏 `red` | `#d70015` | `#ff453a` |

规则：**卡片不用投影**，层级只靠一档色调差 + 1px 分隔线；**强调色只出现在主操作、当前项和唯一图表主线**。

### 6.3 形状与间距

`sheet 12 · card 10 · control 8 · chip 6 · pill 999`；8px 基准，行高 44，内容边距 24，区块间距 32。

### 6.4 控件

- **分段控件**：8px 圆角外框，2px 内嵌 thumb + 极轻投影（唯一允许的静置投影——它是 macOS 标准控件，不是装饰）。
- **开关**：51×31，knob 27，开 = accent，0.2s。
- **主按钮**：accent 实心，8px 圆角，高 32；次要按钮白底 1px 边。
- **徽章**：胶囊，底色为该状态色 12% 透明版，文字用同色深版。

### 6.5 动效

`120ms / 200ms / 320ms`，出场 `cubic-bezier(0.16,1,0.3,1)`。**数字不补间**（每秒多次刷新会抖）；只有曲线、进度、运行脉冲动；尊重 `prefers-reduced-motion`。

## 8. 状态清单（必须都成立）

| 状态 | 界面行为 |
|---|---|
| 未测 | 结论卡显示 `—` +「还没有测过」+ 一句这工具会做什么；下方六项以预告行列出 |
| 探测中 | 分数位显示脉冲占位，**不显示假数字**；行内出现进度与当前阶段 |

| 测不成 | 写明"本轮没有测成，所以不给分数" + 真实原因 |
| 长跑断流 | 时间线在断点处断开标红，给出秒数，而不是"平均 3.8 Mbps" |
| 流断开 | 顶部细条"事件流断开，正在重连"，不弹模态 |
| 长跑倒计时 | 已用 / 剩余 / 已下流量三件套，只在长跑时出现 |

## 9. 现状体检（改之前先认账）

拿真实结果截图（1440×900）对代码比，五个真问题：

1. **单项长跑做不到。** `main.js:142` 强制 `longRun:false`，`ProbeSettingsPanel` 里 P1 时长上限还是 120 秒 —— 用户要的「单独测大文件下载跑 30 分钟」只在"设置页"（作用于完整探测）有入口。概念错位：长跑只影响 P1，却放在全局设置里。
2. **首屏下半屏是空的。** 结论面板只占上半，底部 240px 无内容 —— 说明该放的东西没放进去（三分项被压在结论卡里，条件卡占了主位）。
3. **六项状态带读不出来。** 4px 色条、无文字、hover 才有 title。
4. **长跑没有进度感。** 30 分钟只有"探测中…"和一个滚动计时，不知道还剩多久、已下多少。
5. **取消按钮会跑丢。** 它在配置卡内部，滚动离开就找不到了。

## 13. 需要你拍板的两件事

1. **总评要不要因为单项复测重算？** 我的判断：**不重算**。单项数据算出来的总分，和你以为的"这套代理整体能力"不是一个东西，重算会造新的假结论。现状已按不重算实现。
2. **长跑入口放哪？** 我的判断：**放到分评页 P1 那一行**，同时从设置页移除（或改成"仅作用于完整探测"的说明）。理由：长跑只影响 P1 一项，放在全局设置里会让人以为六项都跑 30 分钟。

这两条你点头，我就按第 10 节的顺序开工。
