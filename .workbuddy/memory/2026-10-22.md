# 2026-10-22（第二轮）· 「结论必须符合实际」专项修复

用户强调核心诉求：**测试结果一定要符合实际情况**。围绕这一条做了 5 处修复，全部有实测证据。

## 发现的失真（按严重度）

**A. 闸门漏判 → 假绿** `internal/score/score.go` `gateOf`
`degraded` / `rate_limited` 既不计入 aiUsable、也不在 p3Blocked 列表里，
导致「P3 降级但 P4 正常」被裁定为 `usable`。
修：任一 AI 端点处于 challenge/region/hijacked/failed/inconclusive/degraded/rate_limited
即 `hardBlock`；网页端（P3/P4）可用数 ≥1 且无 hardBlock 才 usable。
另加 `siteReason()` 覆盖 P3/P4/P5 八种异常，结论句能说清"为什么"。

**B. 截断误报劫持** `internal/probe/http.go`
`Fetch` 用 `MaxBody` 截断读取，`Classify` 却拿截断后的 BodyLen 与 `Content-Length` 比较，
首页一旦 >200KB 就会判 `hijacked`（疑似劫持）。
修：`FetchResult.Truncated = len(body) >= maxBody`，截断判定加 `!f.Truncated` 前置条件。

**C. 取消被记成不可达** `internal/engine/engine.go` + `http.go`
用户点取消 → 在飞请求返 `context canceled` → `classifyError` 落 default → `StatusFailed`，
评分照常跑，把"用户自己按了取消"渲染成"这套代理不可用"。
修：`classifyError` 识别 context.Canceled → `StatusCancelled`；engine 在 `ctx.Err()!=nil` 时
**不产出 Summary**（半程数据不出结论）。前端 VerdictPanel 增加"本次探测已取消"分支，
明确说"不给分数"。

**D. 未测维度当 0 分** `internal/score/score.go`
快速档不测 P1，速度维度 `score=0` 却仍占 40% 权重，总分被拉成 46/D，
用户读成"速度极差"，实际是"没测"。
修：新增 `isMeasured()`，未测维度不参与加权，权重在参与项上重新归一；
`Dimension` 增 `Measured bool`；前端显示「速度 · 未测」+ 虚线空槽 + 分数「—」；
结论句补"本次未测下载速度，速度分不参与总分"。

**E. AI 站点单次采样 = 抽签** `internal/probe/site.go`
P3/P4 原本单次请求就定生死。实测同一分钟内 chatgpt.com 在 200 与 403 challenge 之间反复。
修：P3/P4 改为 3 次采样（间隔 1.2s），`severity()` 取**最差**结论，
证据链输出「第 N 次：HTTP xxx · 状态」分布 + 最差那次的关键响应头；
卡片副标题显示 `n/m 次能打开`，混合时 headline 为「时好时坏」。

# 第三轮 · P1 下载回归修复 + 并发自证（11:10–11:35）

用户指示：**暂不考虑 Windows，聚焦功能与体验**。

## 缺陷：关 HTTP/2 让 P1 全端点超时（自己引入的）

上一轮为让"6 并发"名副其实而禁 h2，写法是 `ForceAttemptHTTP2=false` + 空 `TLSNextProto`。
结果 P1 恒 `failed / 所有下载端点均不可达`，`durationMs=35001`，而 curl 同端点 206 正常。

**根因是 ALPN 错配，不是超时**：
```
malformed HTTP response "\x00\x00\x12\x04...http2_handshake_failed"
```
服务端经 ALPN 选了 h2 并回 SETTINGS 帧，客户端已无 h2 处理器，用 HTTP/1.x 解析该帧 → 报错。
`tr.Clone()` 会把上层为浏览器同构配好的 `TLSClientConfig` 一并带过来。

**四组对照实测**（`/tmp/h1test`，本地无效，直连 dl.google.com）：

| 组合 | 结果 |
|---|---|
| A 允许 h2 | 206 / 426ms / HTTP/2.0 |
| B 仅 `ForceAttemptHTTP2=false` | 失败，malformed HTTP response |
| C 仅空 `TLSNextProto` | 失败，同上 |
| D 两者都设 | 失败，同上 |
| **正解**：`ForceAttemptHTTP2=false` + `TLSClientConfig.NextProtos=["http/1.1"]` | **206 / 329ms / HTTP/1.1** |

结论：必须在 **TLS 层**摘掉 h2。只关 Transport 层不管用；而单独设 `NextProtos` 但保留
`ForceAttemptHTTP2=true` 也不行（Go 的 h2 配置会覆写 NextProtos，仍协商成 h2）。

## 顺带做成"并发自证"

新增 `Result.ConnCount`：下载循环里挂 `httptrace.ClientTrace.GotConn`，按 `LocalAddr`
去重统计真实独立 TCP 数。subline 变成 `dl.google.com · 32.2 MB · 6 并发/6 连接`，
声明与实测不一致时额外在 evidence 里写明。**"N 并发"从此是测出来的，不是写出来的。**
